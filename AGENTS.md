# AGENTS.md

fastAppshipKit is an open-source starter kit that will let a developer pick one mobile platform and run the same slash commands in Claude Code, Cursor, OpenCode, Google Antigravity, or Codex. This repository currently defines the command format, the platform contract, and the compiler. It does not scaffold an app.

Read [docs/SPEC.md](docs/SPEC.md) before editing anything under `commands/` or `platforms/`.

## Layout

```text
commands/<name>/COMMAND.md              platform-neutral Goal, Ask, Verify, Never
platforms/<id>/platform.json            manifest
platforms/<id>/fragments/<name>.md      Preconditions, Steps, Rollback
scripts/lint-commands.mjs               contract check
scripts/compile-commands.mjs            merges one platform into agent command files
docs/SPEC.md                            command format, schemas, and design rules
.shipkit/state.json                     local run state, gitignored
```

Platform ids are `expo`, `flutter`, `android`, and `ios`. Generated command files are named `ship-<name>` and are gitignored. Edit the source files, then compile.

## Design rules

1. Idempotent and resumable. Skip a step already marked `done` for the current `kitVersion`.
2. Ask once in one batch. Ask every question in Ask before Steps, then reuse `.shipkit/state.json` `answers`.
3. Verify each step. Do not mark a step `done` without checking its result.
4. Secrets only in `.env`, and never printed. Do not write them into state, manifests, or the chat transcript.
5. Human gate before anything that spends money or publishes. Stop and wait for an explicit yes.
6. Minimal diffs. Touch only the files the current step names.

## State

`.shipkit/state.json` holds `platform`, `storeTargets`, `kitVersion`, `answers`, and per-command plus per-step `status` and `updatedAt`. The schema and the update procedure are in [docs/SPEC.md](docs/SPEC.md).

Create the file from that schema when it is missing. Write two-space JSON. Update only the command and steps this run touched. A changed `kitVersion` means previous `done` steps must run again.

## Goal

Report whether the toolchain named by the selected platform manifest is available, and record that result in `.shipkit/state.json`.

## Preconditions

- `.shipkit/state.json` exists and `platform` is `flutter`.
- `platforms/flutter/platform.json` exists and its `envChecks` entries name the Flutter SDK and Dart.
- This command only updates `.shipkit/state.json`. Application source is left untouched.

## Ask

No questions. The platform and store targets are read from `.shipkit/state.json`. Do not ask the developer to choose them again.

## Steps

1. Read `.shipkit/state.json` and `package.json`. If `commands.env-check.status` is `done` and `kitVersion` matches `package.json` `version`, report that the check already passed and stop.
2. Set `commands.env-check` to `in_progress` and write the current UTC timestamp.
3. For each object in `platforms/flutter/platform.json` `envChecks`, in order, run `command` and look for `expected` in the combined output. Record that step's status and timestamp. On a mismatch, record `blocked` and include the `install` hint for the current OS in the report. Do not run an installer.
4. Set the command status to `done` when every step matched, otherwise `blocked`, and write the timestamp.

## Verify

Every `envChecks` entry has a step status. The command is `done` only when every check found its `expected` substring. The transcript and state file contain no values from `.env` or other secrets.

## Rollback

Set `commands.env-check.status` to `blocked` and timestamp it. Do not revert machine-level tools. This command must not have changed them. Leave application files untouched so the failed step statuses can be resumed.

## Never

Do not install, upgrade, or remove toolchains. Do not create accounts, spend money, upload a binary, or submit to a store. Do not print `.env` or secret files. Do not edit application source. Do not mark a failed check as `done`.

title: Troubleshooting
description: Failures from npx createshipyard and the slash commands.
---

## The CLI cannot find the kit files

Install and scaffold with `npx createshipyard my-app`. That runs the `createshipyard` package from npm. If Node cannot find the templates, the error is that the App Shipyard files were not found. The command looks for `platforms/expo/platform.json` next to a `package.json` named `createshipyard`.

The directory name has to be a lowercase npm name, such as `my-app`. The folder must be missing or empty.

## iOS on Windows or Linux

`npx createshipyard my-app --platform ios` stops when `process.platform` is not `darwin`, with: iOS native requires macOS and Xcode. Use `expo`, `flutter`, or `android` on that machine.

## Update plan needs state

`/ship-update` reads `.shipkit/state.json`. `npx createshipyard` writes that file. If it is missing, run `npx createshipyard my-app` or `/ship-start` first. The update plan does not edit files until you answer yes.

## Stubs

The Flutter, Android, and iOS templates in the package say they are not buildable projects yet. `publish` blocks when the app is not a working Expo project. The command does not call EAS or open Play Console on its own.

## Toolchain checks

`/ship-env-check` reports pass, fail, or skipped. It does not install a toolchain unless you say yes after the failed checks are on screen. Xcode and CocoaPods are skipped off macOS when the install hint starts with `macOS only:`.

A failed check is not marked done.

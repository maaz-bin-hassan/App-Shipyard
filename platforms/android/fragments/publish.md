## Preconditions

- `.shipkit/state.json` exists and `platform` is `android`.
- `storeTargets` includes `play`.
- `docs/play-console-checklist.md` exists.
- A working app has `settings.gradle` or `settings.gradle.kts` and `app/` at the repo root. The Android template in this kit is still a stub.
- Run every command from the repository root. Do not use EAS.

## Steps

1. Read `.shipkit/state.json` and `package.json`. If the state file is missing, create it with `platform` null, `storeTargets` [], `kitVersion` from `package.json` `version`, `answers` {}, and `commands` {}. Write two-space JSON. If `platform` is not `android`, or `storeTargets` does not include `play`, set `commands.publish.status` to `blocked` and stop. If `commands.publish.status` is `done` and `kitVersion` matches `package.json` `version`, report that publish already finished and stop. Skip a step already `done` only when `kitVersion` still matches. Record the answers from Ask. If the Gradle settings file or `app/` is missing, set step `1` and `commands.publish` to `blocked` and stop. Do not create an Android project here. When the project exists, set step `1` and the command to `in_progress`. Re-read the checklist asset pages and update the checklist when a page disagrees. Write the 512×512 listing icon and the 1024×500 feature graphic into `fastlane/metadata/android/<locale>/images/`, measured as the checklist describes. Update the existing adaptive icon layers to 108×108 dp with the mark inside the center 66×66 dp. Record step `1` as `blocked` when a measured file fails, otherwise `done`.

2. Skip when step `2` is `done` and `kitVersion` matches. Set step `2` and the command to `in_progress`. Capture four phone screens from an API 36 emulator with `adb exec-out screencap -p`. Export `fastlane/metadata/android/<locale>/images/phoneScreenshots/01.png` through `04.png` at 1080×1920, 24-bit PNG, no alpha. Honor `answers.screenshotStyle`. Write alt text to `docs/play/screenshot-alt-<locale>.md`. Record step `2` as `blocked` when a file fails or the emulator is missing, otherwise `done`.

3. Skip when step `3` is `done` and `kitVersion` matches. Set step `3` and the command to `in_progress`. Write `title.txt`, `short_description.txt`, `full_description.txt`, and `keywords.txt` for each locale, within 30, 80, and 4000 characters, with no trailing newline. Keep the keyword list out of the three listing files. Show the draft and ask `approveListingCopy` once. Record step `3` as `blocked` until that answer is `yes` and the limits hold, otherwise `done`.

4. Skip when step `4` is `done` and `kitVersion` matches. Set step `4` and the command to `in_progress`. Ignore `allowEasCredentials`. When `answers.allowBuild` is not `yes`, record step `4` as `blocked` and stop. Keep the upload keystore outside the repo. Read `ANDROID_KEYSTORE_PATH`, `ANDROID_KEYSTORE_ALIAS`, `ANDROID_KEY_PASSWORD`, and `ANDROID_STORE_PASSWORD` from `.env` without printing them. Do not pass `-storepass` on the command line. Confirm `key.properties` is gitignored when the project uses it. Run `./gradlew :app:bundleRelease`. Read `targetSdkVersion` from the app Gradle file or the build log. Record step `4` as `blocked` when the build fails, the output is not an `.aab`, or the target is missing or below 36. Otherwise record `answers.playVersionCode` and set step `4` to `done`.

5. Skip when step `5` is `done` and `kitVersion` matches. Set step `5` and the command to `in_progress`. Walk `docs/play-console-checklist.md` from Create the app through Store listing and contact. The developer clicks. `allowCreatePlayApp` covers Create app and is skipped when `answers.playAppExists` is `yes`. `allowPlaySetup` covers the policy screens and the listing. Copy Data safety from this app's `docs/legal/data-safety-answers.md` only after `commands.legal` is `done` for this app. The Expo legal draft is not this app's policy. When this app has no legal draft of its own, record the Data safety screen as `blocked` and stop. Record `answers.playScreens.<id>` as `saved` after each confirmation. Record step `5` as `done` only when every screen in that range is `saved`.

6. Skip when step `6` is `done` and `kitVersion` matches. Set step `6` and the command to `in_progress`. Do not run `eas submit`. The first upload is the manual path in the checklist, on Test and release > Testing > Internal testing. `answers.allowInternalUpload` must be `yes`. Rollout also needs `answers.allowInternalPublish` = `yes` and a non-empty `answers.internalTesterEmails`. Choose the Google-generated Play app signing key if the console asks. Do not click Promote release. Record step `6` as `done` only when the developer confirms the internal track shows the release rolled out.

7. When `answers.cutLaterRelease` is not `yes`, record step `7` as `skipped` and continue. When it is `yes`, require `answers.allowLaterSubmit` = `yes` and a higher `versionCode` at most 2100000000. Build a new app bundle as in step 4 and upload it on the internal track. When `answers.allowSupplySync` is `yes`, run the supply command from the checklist with the bundle upload skipped only after `answers.allowServiceAccount` is `yes`. When a listing sync was requested and that gate is not `yes`, record step `7` as `blocked` and do not run supply. Record step `7` as `done` when the new internal release is confirmed and any requested listing sync has finished, otherwise `blocked`.

8. Skip when step `8` is `done` and `kitVersion` matches. Run the checklist pre-launch checks against the rolled-out version. Record step `8` as `blocked` when any applicable check fails. Set `commands.publish.status` to `done` only when steps `1` through `6` and step `8` are `done` and step `7` is `done` or `skipped`. Write UTC timestamps.

## Rollback

Set `commands.publish.status` to `blocked` and timestamp it. Leave listing files, the app bundle, and the Play app in place. Do not halt or promote a release. Do not print secrets or delete `.shipkit/state.json`.

## Preconditions

- `.shipkit/state.json` exists and `platform` is `expo`.
- `storeTargets` includes `play`.
- `docs/play-console-checklist.md` exists. Asset sizes and click paths come from that file.
- A working app has a root `package.json` that depends on `expo`, a name other than `fastappshipkit`, and `app.json`, `app.config.js`, or `app.config.ts` at the repo root.
- Run every command from the repository root.

## Steps

1. Read `.shipkit/state.json` and `package.json`. If the state file is missing, create it with `platform` null, `storeTargets` [], `kitVersion` from `package.json` `version`, `answers` {}, and `commands` {}. Write two-space JSON. If `platform` is not `expo`, or `storeTargets` does not include `play`, set `commands.publish.status` to `blocked` and stop. If `commands.publish.status` is `done` and `kitVersion` matches `package.json` `version`, report that publish already finished and stop. A step whose status is `done` is skipped only when `kitVersion` still matches. Record the answers from Ask, including a blank `iconSource`. If the root package is not a working Expo app, set step `1` and `commands.publish` to `blocked` and stop. The kit template is not a buildable app. Do not generate icons, call EAS, or open Play Console in that checkout. When the app is a working Expo app, open the checklist's cited pages for the asset table. When a page disagrees with the checklist, update the checklist from the page before writing files. Then set step `1` and `commands.publish` to `in_progress` and write the current UTC timestamp. From `answers.iconSource` or `answers.iconBrief` and `answers.primaryColor`, write `assets/images/icon.png`, `assets/images/adaptive-icon.png`, and `assets/images/adaptive-monochrome.png` at 1024×1024. Keep the mark inside the center 66/108 of the adaptive layers. Write each `fastlane/metadata/android/<locale>/images/icon.png` at 512×512, 32-bit PNG with alpha, 1024 KB or smaller, full square, sRGB, with no badge and no pre-rounded mask. Write `featureGraphic.png` at 1024×500 as a 24-bit PNG with no alpha. Point the app config `icon`, `android.adaptiveIcon.foregroundImage`, `android.adaptiveIcon.monochromeImage`, and `android.adaptiveIcon.backgroundColor` at those files and at `answers.primaryColor`. Set `android.package` to `answers.applicationId` when it still has a placeholder. Measure every PNG from its IHDR, as the checklist describes. Record step `1` as `blocked` when any file fails, otherwise `done`.

2. Skip when step `2` is `done` and `kitVersion` matches. Set step `2` and the command to `in_progress` and write the UTC timestamp. Capture at least four phone screens from an API 36 emulator with `adb exec-out screencap -p`. Export each locale's set to `fastlane/metadata/android/<locale>/images/phoneScreenshots/01.png` through `04.png` at 1080×1920, 24-bit PNG, color type 2. When `answers.screenshotStyle` is `framed`, compose the frame and the caption inside that canvas, with the caption at or under 20% of the image. When it is `raw`, export the capture with no frame and no caption. Recapture a locale whose caption is translated. Clean the status bar. Write alt text, 140 characters or fewer, to `docs/play/screenshot-alt-<locale>.md`. Do not use a ranking, price, or call-to-action caption. Record step `2` as `blocked` when a file fails the checklist measurement, when the emulator is missing, or when a caption locale was not recaptured. Otherwise `done`.

3. Skip when step `3` is `done` and `kitVersion` matches. Set step `3` and the command to `in_progress` and write the UTC timestamp. For each Play locale, write `title.txt`, `short_description.txt`, `full_description.txt`, and `keywords.txt` under `fastlane/metadata/android/<locale>/`. Prefer `docs/store/listing-<tag>.md` when it exists. Count code points after trim. Title ≤ 30, short description ≤ 80, full description ≤ 4000. Write the text files with no trailing newline. Keep `keywords.txt` out of the three listing files. Drop ranking words, calls to action, emojis, and line breaks from the short description. Show the draft and ask `approveListingCopy` once. Record step `3` as `blocked` until that answer is `yes` and every file is within its limit, otherwise `done`.

4. Skip when step `4` is `done` and `kitVersion` matches. Set step `4` and the command to `in_progress` and write the UTC timestamp. When `answers.allowBuild` or `answers.allowEasCredentials` is not `yes`, record step `4` as `blocked` and stop. Do not run `eas build` or `eas credentials`. When `eas` is not on the path, show the install line from the EAS submit docs and wait for an explicit yes before installing. Do not pass `--auto-submit`. If `eas.json` has no production Android build that produces an app bundle, add only `build.production.android.buildType` = `app-bundle`. Leave an existing production profile that already builds an `.aab` as it is. When that profile sets `buildType` to `apk`, record step `4` as `blocked` and stop. Let EAS generate the upload keystore when the application id does not have one, and leave it on EAS. Do not download it. If the CLI prints a keystore password, keep it out of the transcript, state, and git. Run `eas build --platform android --profile production`. Read the build log for `targetSdkVersion`. Record step `4` as `blocked` when the build fails, the artifact is not an `.aab`, or `targetSdkVersion` is missing or below 36. Otherwise record `answers.playVersionCode` from the build and set step `4` to `done`.

5. Skip when step `5` is `done` and `kitVersion` matches. Set step `5` and the command to `in_progress` and write the UTC timestamp. Re-read the checklist pages for the screens below. Update the checklist when a page has moved, then follow the updated path. Walk `docs/play-console-checklist.md` from Create the app through Store listing and contact. The developer clicks. You supply the path and the value table. Record `answers.playScreens.<id>` as `saved` only after they confirm that screen. Stop the step when a gate is not `yes`. `allowCreatePlayApp` covers Home > Create app, and is skipped when `answers.playAppExists` is `yes`. `allowPlaySetup` covers privacy policy, ads, sign-in details, target audience, content rating, Data safety, and the store listing. Enter the privacy URL only when `answers.privacyPolicyReviewed` is `yes`. Block Data safety until `commands.legal.status` is `done` and the answers are copied from `docs/legal/data-safety-answers.md`. Stop before Save on target audience when a band includes children under 13. Do not invent a content rating, a test account, or an ads answer. If News or COVID-19 appears under Needs attention, answer it from the app and do not claim either for this template. Record step `5` as `blocked` when any of those screens is not `saved`, otherwise `done`.

6. Skip when step `6` is `done` and `kitVersion` matches. Set step `6` and the command to `in_progress` and write the UTC timestamp. This stage needs `answers.allowInternalUpload` = `yes`. Rollout also needs `answers.allowInternalPublish` = `yes` and at least one address in `answers.internalTesterEmails`. Follow the checklist's Internal testing release and First upload sections. When `answers.firstUploadPath` is `manual`, the developer uploads the `.aab` from step 4 on Test and release > Testing > Internal testing. When it is `eas`, show the submit-guide paragraph and the security-page paragraph from the checklist, require `answers.allowServiceAccount` = `yes`, and complete the service-account section before `eas submit`. Add `submit.internal.android` in `eas.json` with `track` `internal`, `serviceAccountKeyPath` `$GOOGLE_SERVICE_ACCOUNT_KEY_PATH`, and `releaseStatus` `draft`, or `completed` when rollout is already approved. Do not change an existing production submit profile. Run `eas submit --platform android --profile internal` only for the `eas` path. Choose the Google-generated Play app signing key if the console asks. The developer clicks Save and publish, or the internal-track rollout control, only after `allowInternalPublish` is `yes`. Do not click Promote release. Record `answers.playVersionCode` and set step `6` to `done` only when the developer confirms the internal track shows that version rolled out. A draft leaves the step `blocked`.

7. When `answers.cutLaterRelease` is not `yes`, record step `7` as `skipped` and continue. When it is `yes`, set step `7` and the command to `in_progress`. Require `answers.allowLaterSubmit` = `yes` and a `versionCode` greater than `answers.playVersionCode` and at most 2100000000. Repeat the build gate from step 4 for the new bundle. Submit with `eas submit --platform android --profile internal` to the internal track only, after `answers.allowServiceAccount` is `yes` and the key is assigned. When `answers.allowSupplySync` is `yes`, run the supply command from the checklist with the bundle upload skipped. When it is not `yes`, leave the listing files local and record step `7` as `blocked` if a listing sync was required, otherwise `done` after the internal upload is confirmed. Do not echo the service-account file. Record step `7` as `blocked` when the new bundle is not on the internal track.

8. Skip when step `8` is `done` and `kitVersion` matches. Set step `8` and the command to `in_progress` and write the UTC timestamp. Run the pre-launch checks in the checklist against the version from step 6, or from step 7 when that step is `done`. A free app, or a skipped paywall, records the paywall check as not applicable. Record step `8` as `blocked` when the session crashes, the paywall check fails, the privacy URL is not a public 200, or a listing link fails. Otherwise `done`. Set `commands.publish.status` to `done` only when steps `1` through `6` and step `8` are `done` and step `7` is `done` or `skipped`. Write UTC timestamps.

## Rollback

Set `commands.publish.status` to `blocked` and timestamp it. Leave generated images, listing files, `eas.json`, and the Play app in place. Do not halt, promote, or unpublish a release. Do not delete a keystore or a service-account file. Do not print secrets. Do not delete `.shipkit/state.json`.

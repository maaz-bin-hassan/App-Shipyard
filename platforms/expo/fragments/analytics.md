## Preconditions

- `.shipkit/state.json` exists and `platform` is `expo`.
- `platforms/expo/template/src/lib/analytics.ts` and `docs/analytics-setup.md` exist.
- Run every command from the repository root.

## Steps

1. Read `.shipkit/state.json` and `package.json`. If the state file is missing, create it with `platform` null, `storeTargets` [], `kitVersion` from `package.json` `version`, `answers` {}, and `commands` {}. Write two-space JSON. If `platform` is not `expo`, set `commands.analytics.status` to `blocked` and stop. If `commands.analytics.status` is `done`, `kitVersion` matches `package.json` `version`, and `docs/events.md` matches `renderEventsMarkdown()`, report that analytics already finished and stop. Otherwise record step `1` as `done`.
2. Set `commands.analytics` and step `2` to `in_progress` and write the current UTC timestamp. Write `answers.posthogHost`, `answers.sentryOrganization`, and `answers.sentryProject` from Ask. Write `docs/events.md` with the string from `renderEventsMarkdown()` in `platforms/expo/template/src/lib/events.ts`, replacing the file when it already exists. Copy these template files to the same path under the app when that destination is missing, and leave an existing file as it is: `src/lib/analytics.ts`, `src/lib/events.ts`, `src/lib/posthog.ts`, `src/lib/sentry.ts`, `src/lib/consent.ts`, `src/ui/host.ts`, `src/features/settings/copy.ts`, and `src/features/settings/AnalyticsConsentSetting.ts`. The copies come from `platforms/expo/template/`. If the checkout has no app source root, leave the files in the template. Record step `2` as `done`.
3. If the checkout has no `app.json` and no `app.config.js` or `app.config.ts`, this is still the kit repo. Leave the module in the template. Record step `3` as `skipped`. When an Expo app config exists, run `npx expo install posthog-react-native expo-file-system expo-application expo-device expo-localization @sentry/react-native`. Ensure `.env` contains `EXPO_PUBLIC_POSTHOG_API_KEY`, `EXPO_PUBLIC_POSTHOG_HOST`, and `EXPO_PUBLIC_SENTRY_DSN` without printing their values. Set `EXPO_PUBLIC_POSTHOG_HOST` from `answers.posthogHost`. Build PostHog with `defaultOptIn: false` and pass `bindPostHog` into `createAnalytics` with `consent: false`. Pass `bindSentry` the same way. Mount `AnalyticsConsentSetting` on the settings screen. When `node_modules/react-native` exists, re-export `View`, `Text`, and `Pressable` from `react-native` in `src/ui/host.ts`. Record step `3` as `blocked` when install fails or a public key name is missing, otherwise `done`.
4. If step `3` was `skipped`, record step `4` as `skipped`. Otherwise merge the Sentry plugin and the Metro config from `docs/analytics-setup.md` into the app. Use `answers.sentryOrganization` and `answers.sentryProject`. Do not write `SENTRY_AUTH_TOKEN` into those files. Tell the developer to set `SENTRY_AUTH_TOKEN` as an EAS environment variable for the build profile. Wait for confirmation that the name is set. Do not ask them to paste the token. Record step `4` as `done` when they confirm, and `blocked` when they stop before that.
5. Run `pnpm test:analytics`. Record step `5` as `blocked` when it fails, otherwise `done`.
6. If step `3` was `skipped`, record step `6` as `blocked`, set `commands.analytics.status` to `blocked`, and stop. The template and the event list are in place. The live check waits for an Expo app. When an app exists, turn consent on, send one catalog event, and confirm it in PostHog. Then call `captureException` once and confirm the issue in Sentry with source-mapped frames. Record step `6` as `done` only when both are visible. Set `commands.analytics.status` to `done` only when step `6` is `done`. Write UTC timestamps.

## Rollback

Set `commands.analytics.status` to `blocked` and timestamp it. Leave the template, `docs/events.md`, and `.env` in place. Do not print `.env`. Do not delete `.shipkit/state.json`.

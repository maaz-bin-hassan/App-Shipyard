## Preconditions

- `.shipkit/state.json` exists and `platform` is `expo`.
- `answers.languages` is a non-empty array, or Ask just recorded one.
- `platforms/expo/template/src/i18n/locales/en.json` exists. `platforms/expo/template/package.json` lists `i18next` and `expo-localization`.
- `platforms/expo/platform.json` `stringsFormat` is `json`.
- Run every command from the repository root.

## Steps

1. Read `.shipkit/state.json` and `package.json`. If the state file is missing, create it with `platform` null, `storeTargets` [], `kitVersion` from `package.json` `version`, `answers` {}, and `commands` {}. Write two-space JSON. If `platform` is not `expo`, set `commands.translate.status` to `blocked` and stop. If `answers.languages` is missing or empty, set `commands.translate.status` to `blocked` and stop. If `commands.translate.status` is `done`, `kitVersion` matches `package.json` `version`, and every tag in `answers.languages` has a locale file with no `missingKeys` against English, report that translate already finished and stop. Otherwise record step `1` as `done`.
2. Set `commands.translate` and step `2` to `in_progress` and write the current UTC timestamp. If the checkout has no `app.json` and no `app.config.js` or `app.config.ts`, this is still the kit repo. Do not run an installer. Confirm `platforms/expo/template/package.json` lists `i18next` and `expo-localization`. Record step `2` as `done` when both names are there, and `blocked` when one is missing. When an Expo app config exists, run `npx expo install i18next expo-localization` if either package is missing from the app `package.json`. Record step `2` as `blocked` when that install fails, otherwise `done`.
3. Keep English in `src/i18n/locales/en.json` and the matching object in `src/i18n/locales/en.ts`. The template catalog already holds the permission, settings, billing, and error strings. `pnpm test:i18n` fails when those two files differ. i18next loads the JSON. The TypeScript object is what Node tests import. Search screens for a user-facing literal that is not in that file, add a stable key, and replace the literal with `translate` or `useI18n`. Do not edit a string that is already a key. Copy `src/i18n` from `platforms/expo/template` when the app is missing it. In an Expo app, call `setupI18next` with the `i18next` instance, `expo-localization`'s `getLocales`, the locale JSON, and React Native `I18nManager`. `directionFor` decides layout. Do not trust a device `textDirection` of `ltr` for `ar` or `ur`. Record step `3` as `done` when English keys resolve and the app path calls `setupI18next`, or when this checkout is still the kit and the template catalog is the source.
4. For each tag in `answers.languages` other than `en`, write `src/i18n/locales/<tag>.json` with the same keys as English. Translate the values yourself. Do not call a translation API. `missingKeys(en, catalog)` must be empty. For `ar` and `ur`, `directionFor` is `rtl` and `applyLayoutDirection` calls `forceRTL(true)`. Record step `4` as `blocked` when a key is missing or `ar` or `ur` is left-to-right, otherwise `done`.
5. For each tag in `answers.languages`, write `docs/i18n/review-<tag>.md` with `renderNativeReview`. The file lists every key and says a native speaker should review it. Write `docs/store/listing-<tag>.md` with `renderStoreListing`, using `answers.storeTargets` and copy you write from `answers.appName` and the product facts already in `answers`. Do not add a feature the app does not have. If a store field is empty or over the limit printed in that file, record step `5` as `blocked` and ask the developer to shorten it. Otherwise record step `5` as `done`.
6. Run `pnpm test:i18n`. Record step `6` as `blocked` when it fails, otherwise `done`.
7. If step `2` did not install into an app, record step `7` as `blocked`, set `commands.translate.status` to `blocked`, and stop. The catalogs and the RTL checks are in the template. The device walk waits for an Expo app. When an app exists, switch the device language to each tag, walk each screen, and for `ar` and `ur` confirm the layout is RTL. Record step `7` as `done` only when the developer confirms that walk. Set `commands.translate.status` to `done` only when step `7` is `done`. Write UTC timestamps.

## Rollback

Set `commands.translate.status` to `blocked` and timestamp it. Leave locale files, review files, and store listings in place. Do not delete `.shipkit/state.json`.
